# Pathwise — UI/UX Design & Implementation Instruction

## 1. PRODUCT

Build a premium AI-powered personalized learning platform called **Pathwise**.

### Product tagline

**Your goal. Your path. Your pace.**

### Core idea

Pathwise takes a learner's natural-language career or learning goal, understands their current skills, experience, interests, available study time and preferences, identifies skill gaps, and generates an adaptive learning roadmap containing:

* Courses
* Skills
* Projects
* Assessments
* Milestones
* Prerequisites
* Progress tracking
* AI explanations
* Next recommended actions

The product must feel like a **real learning product**, not an AI demo or generic SaaS dashboard.

---

# 2. DESIGN OBJECTIVE

The most important design requirement is:

> **Make the interface look intentionally designed by a professional product design team, not generated by AI.**

Avoid the visual patterns commonly associated with AI-generated websites:

* Excessive purple gradients
* Giant glowing blobs
* Random floating glass cards
* Excessive rounded cards
* Every section using a different visual effect
* Robot/AI illustrations everywhere
* Excessive neon glow
* Generic "AI-powered" labels
* Huge centered SaaS hero sections
* Unnecessary 3D objects
* Excessive animations
* Decorative elements without meaning
* Dashboard containing dozens of unrelated statistics
* Generic card grids
* Excessive use of emojis
* Purple gradient text everywhere

The interface should feel:

* Premium
* Intelligent
* Calm
* Technical
* Human
* Structured
* Trustworthy
* Modern
* Purposeful

# 4. DESIGN PERSONALITY

Pathwise should feel like:

**Linear + modern developer tooling + premium education platform + subtle HCLTech energy**

NOT:

**ChatGPT clone + glassmorphism + purple gradient + AI robot**

The product's own subject matter should define its visual language.

The main visual metaphor is:

> **A learner moving from their current state toward a specific goal.**

Therefore use:

* Paths
* Nodes
* Connections
* Progress
* Milestones
* Skill levels
* Direction
* Prerequisites
* Checkpoints

These should be visual design elements because they represent real product concepts.

# 9. GLASSMORPHISM RULE

Glass effects are allowed but must be used sparingly.

DO NOT make every card glass.

Use glass only for:

* AI Mentor floating interface
* Important overlays
* Floating navigation
* Selected path node
* Contextual popovers
* One or two hero interactions

Most dashboard surfaces should be:

* Solid dark surfaces
* Thin borders
* Subtle shadows

The uploaded Liquid Glass JS skill specifically recommends keeping refraction subtle and providing a normal blur fallback. Follow that principle.

# 29. MOTION

Motion should be subtle and intentional.

Use:

* Fade in
* Slide in
* Scale in
* Stagger
* Layout animation
* Shared element transitions where appropriate
* Hover effects
* Press feedback
* Smooth path transitions

The uploaded animation vocabulary defines these patterns and should be used as the terminology when describing motion.

Use GSAP only when animation sequencing genuinely requires it. The uploaded GSAP skill recommends transform/opacity animation and respecting reduced motion.

### Motion rules

```text
Page entrance:       400–700ms
Micro interaction:   150–250ms
Panel transition:    250–400ms
Major transition:    500–800ms
```

Avoid:

* Constant floating animations
* Infinite pulsing
* Excessive parallax
* Bouncy cards
* Every element animating independently
* Scroll animations on every section

# 31. 3D RULE

3D/WebGL is optional.

Do NOT add 3D just because the stack contains React Three Fiber.

If used, use it for:

* subtle background depth
* path visualization
* interactive skill dependency graph

Do not create:

* floating planets
* random cubes
* abstract 3D objects
* unnecessary particle fields

The uploaded R3F skill specifically recommends using R3F when the React application genuinely requires 3D/WebGL, not for ordinary 2D UI.

# 44. DESIGN REVIEW BEFORE CODING

Before writing the UI, internally evaluate:

### Question 1

Would this design look almost identical if the product were changed from education to CRM?

If yes → redesign it.

### Question 2

Does this component communicate something specific about learning?

If no → remove or simplify it.

### Question 3

Is the AI visually present because it is useful, or simply because the project uses AI?

If the latter → remove it.

### Question 4

Is the purple accent helping hierarchy?

If not → reduce it.

### Question 5

Can a user understand their next learning action within 5 seconds?

If not → improve the hierarchy.

---

# 45. FINAL DESIGN PRINCIPLE

The interface should communicate:

> **"Pathwise understands where I am, knows where I want to go, and can clearly explain how I get there."**

Every major UI decision should reinforce that idea.

The final product must look like a **real startup-quality learning product that could be shipped**, not a hackathon landing-page concept.

Build for clarity first, personality second, effects third.
